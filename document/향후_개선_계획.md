## ✅ 개선 포인트 1: 날짜 특성 Encoder-only 처리

### 현재 문제점
- **날짜 특성(date_features)이 매 timestep에 21차원씩 반복됨**
- 시간 특성(time_features) 대비 weight가 약 3배 이상 강함
- 불필요한 중복 정보로 인한 학습 비효율

### 개선 방법
```python
# 현재: 모든 timestep에 date_features 복제
date_features_expanded = date_features.unsqueeze(1).unsqueeze(2).expand(-1, seq_len, num_nodes, -1)
# [B, T, N, 21] - 모든 timestep에 동일한 날짜 정보

# 개선: 첫 timestep에만 concat, 나머지는 0-padding
date_features_first = date_features.unsqueeze(1).unsqueeze(2).expand(-1, 1, num_nodes, -1)  # [B, 1, N, 21]
date_features_rest = torch.zeros(batch_size, seq_len-1, num_nodes, 21)  # [B, T-1, N, 21]
date_features_expanded = torch.cat([date_features_first, date_features_rest], dim=1)
```

### 예상 효과
- 날짜 특성의 과도한 영향 감소
- 시간 특성과의 균형 개선
- 학습 안정성 향상

## ✅ 개선 포인트 2: Spatial Attention 추가

### 현재 문제점
- **시간적 Attention만 존재** (encoder timestep 간 attention)
- 공간적(역별) 중요도 정보 미활용
- 환승역/중심역 등 중요 역에 대한 가중치 부재

### 개선 방법
```python
class SpatialAttention(nn.Module):
    """역별 중요도 기반 Spatial Attention"""
    def __init__(self, hidden_size):
        super().__init__()
        self.W = nn.Linear(hidden_size, hidden_size)
        self.v = nn.Linear(hidden_size, 1)
        
    def forward(self, hidden_states):
        # hidden_states: [B, N, H] - 각 역의 hidden state
        # 역별 중요도 계산
        attention_scores = self.v(torch.tanh(self.W(hidden_states)))  # [B, N, 1]
        attention_weights = F.softmax(attention_scores, dim=1)
        
        # 가중 평균
        context = (attention_weights * hidden_states).sum(dim=1)  # [B, H]
        return context, attention_weights
```

### 예상 효과
- 환승역/중심역 중심 예측 정확도 상승
- 역별 중요도 학습 가능
- 공간적 패턴 인식 개선

### 구현 위치
- `models/dcrnn_layers.py`: `SpatialAttention` 클래스 추가
- `models/dcrnn_layers.py`: `DCRNN` 클래스에 통합

## ✅ 개선 포인트 3: Graph Diffusion Normalization Precompute

### 현재 문제점
- **매 batch마다 degree matrix 계산** (D_O^-1, D_I^-1)
- Forward pass 속도 저하
- 불필요한 반복 계산

### 개선 방법
```python
# 현재: 매 forward마다 계산
def forward(self, x, adjacency):
    D_O = torch.sum(adjacency, dim=-1)  # 매번 계산
    D_I = torch.sum(adjacency, dim=-2)  # 매번 계산
    # ...

# 개선: 초기화 시 precompute
def __init__(self, ...):
    # ...
    self.register_buffer('degree_out', None)
    self.register_buffer('degree_in', None)
    
def precompute_degree(self, adjacency):
    """인접행렬이 고정된 경우 한 번만 계산"""
    self.degree_out = torch.sum(adjacency, dim=-1, keepdim=True) + 1e-6
    self.degree_in = torch.sum(adjacency, dim=-2, keepdim=True) + 1e-6
```

### 예상 효과
- Forward pass 속도 개선 (약 10-20% 예상)
- 메모리 효율성 향상
- 학습 시간 단축

### 구현 위치
- `models/dcrnn_layers.py`: `DiffusionConvolution` 클래스 수정
- `scripts/train_occupancy_model.py`: 모델 초기화 후 `precompute_degree` 호출

## ✅ 개선 포인트 4: 승하차 역별 정규화

### 현재 문제점
- **승하차 정규화: `sqrt(x)/15` (전역 정규화)**
- 각 역마다 승하차 규모가 다름
- 대형역(대전역)과 소형역의 스케일 차이 미반영

### 개선 방법
```python
# 현재: 전역 정규화
X_boarding_normalized = torch.sqrt(X_boarding) / 15.0

# 개선: 역별 정규화
# 1. 학습 데이터에서 역별 평균/표준편차 계산
station_boarding_stats = {}  # {station_idx: (mean, std)}
for station_idx in range(num_stations):
    station_data = train_boarding_data[:, station_idx]
    station_boarding_stats[station_idx] = (
        torch.sqrt(station_data).mean(),
        torch.sqrt(station_data).std() + 1e-6
    )

# 2. 역별 정규화 적용
X_boarding_normalized = torch.zeros_like(X_boarding)
for station_idx in range(num_stations):
    mean, std = station_boarding_stats[station_idx]
    X_boarding_normalized[:, station_idx] = (
        (torch.sqrt(X_boarding[:, station_idx]) - mean) / std
    )
```

### 예상 효과
- 역별 스케일 차이 반영
- 소형역 예측 정확도 개선
- 균형잡힌 학습

### 구현 위치
- `scripts/train_occupancy_model.py`: `OccupancyDataset._preprocess_boarding_alighting` 수정
- 역별 통계 저장: `data/boarding_alighting_stats.pkl`

## ✅ 개선 포인트 5: Temporal Consistency Loss 활용

### 현재 문제점
- **TemporalConsistencyLoss가 구현되어 있지만 사용 안 함**
- 큰 혼잡도에 대한 가중치만 적용
- 시간적 연속성 제약 부재

### 개선 방법
```python
# 현재: MAE만 사용
loss = F.l1_loss(predictions, targets)

# 개선: Temporal Consistency Loss 추가
from models.losses import TemporalConsistencyLoss

temporal_loss_fn = TemporalConsistencyLoss(alpha=0.1)

# 학습 루프에서
loss = F.l1_loss(predictions, targets)
temporal_loss = temporal_loss_fn(predictions, previous_predictions)  # 이전 timestep과의 일관성
total_loss = loss + 0.1 * temporal_loss
```

### TemporalConsistencyLoss 구현 확인
```python
# models/losses.py에 이미 구현되어 있음
class TemporalConsistencyLoss(nn.Module):
    """시간적 일관성 손실"""
    def forward(self, pred_t, pred_t_minus_1):
        # 연속된 timestep 간 예측 차이 최소화
        return F.mse_loss(pred_t, pred_t_minus_1)
```

### 예상 효과
- 시간적 연속성 보장
- 예측 안정성 향상
- 급격한 변화 방지

### 구현 위치
- `scripts/train_occupancy_model.py`: `OccupancyTrainer` 클래스 수정
- Loss 계산 부분에 `TemporalConsistencyLoss` 추가

## ✅ 개선 포인트 6: Multi-step Forecasting

### 현재 문제점
- **1-step만 예측** (12시간 입력 → 1시간 예측)
- 단기 예측에만 집중
- 중장기 예측 불가능

### 개선 방법
```python
# 현재: 1-step 예측
target_length = 1
predictions = model(x, adjacency, target_length=1)  # [B, 1, N, 1]

# 개선: Multi-step 예측
target_length = 3  # 3시간 예측
predictions = model(x, adjacency, target_length=3)  # [B, 3, N, 1]

# Loss 계산
loss = 0
for t in range(target_length):
    loss += F.l1_loss(predictions[:, t], targets[:, t])
loss = loss / target_length
```

### 예상 효과
- 중장기 예측 가능
- 실용성 향상
- 운영 계획 수립에 활용 가능

### 구현 위치
- `config/model_config.yaml`: `output_length` 설정 추가
- `scripts/train_occupancy_model.py`: `OccupancyDataset` 수정
- `models/dcrnn_layers.py`: `DCRNN.forward` 이미 지원 (target_length 파라미터)
